# 书籍搜索相关性过滤与排序设计

## 目标

在保留书名副标题和作者搜索能力的前提下，过滤远程书源返回的明显无关书籍，并让最相关结果优先显示。单书源、多书源和 SSE 搜索采用同一套判断规则，返回结果严格限制为 50 条。

## 现状与根因

当前搜索把关键词交给远程书源后，直接解析并返回书源页面中的全部列表项。解析器和前端都不校验书名或作者是否与关键词相关；多书源搜索只做精确去重。因此书源搜索地址失效、站点返回推荐列表或 `bookList` 规则过宽时，大量无关书会被展示。

## 推荐方案

采用后置的混合相关性策略：

1. 规范化关键词、书名和作者。
2. 为结果计算相关性等级。
3. 正常关键词过滤无匹配结果；过短关键词只排序，不硬过滤。
4. 按相关性稳定排序，保留书源原始顺序作为同分顺序。
5. 去重后施加 50 条硬上限。

这比纯硬过滤更能保留副标题和作者搜索，也比只排序更能解决无关结果过多的问题。

## 规范化规则

规范化函数用于匹配和去重，不修改返回给前端的原始书名与作者：

- 转为小写；
- 删除所有 Unicode 空白字符；
- 删除常见中英文书名符号和分隔标点，例如 `《》〈〉「」『』()（）[]【】·-—_:：,，.。`；
- 作者额外移除开头的 `作者` 与其后的冒号。

如果规范化后的关键词为空，则不返回搜索结果。

## 相关性等级

从高到低：

1. 规范化书名与关键词完全相同；
2. 书名以关键词开头；
3. 书名包含关键词；
4. 作者与关键词完全相同；
5. 作者包含关键词；
6. 无匹配。

不使用简介、分类和最新章节参与匹配，避免宽泛文本再次扩大召回。

“过短关键词”定义为：规范化后少于 2 个字符，或者仅由 ASCII 字母/数字组成且少于 3 个字符。短关键词保留无匹配结果，但相关结果仍排在前面；其他关键词删除无匹配结果。

## 代码边界与数据流

新增一个纯 Rust 搜索相关性模块，负责：

- 字段规范化；
- 相关性等级计算；
- 稳定过滤、排序和截断。

`BookService::search_book` 在解析书源响应后调用该模块，使单源接口和每个多源任务首先清除无关项。普通多源接口在合并去重后再次按同一关键词全局排序并截断。

SSE 搜索继续逐书源流式返回，避免等待所有慢书源；每个批次按相关性排序，服务端发送前按剩余名额截断，保证整次流最多返回 50 条。由于结果是流式到达，跨书源的全局顺序不作保证，但无关结果过滤和硬上限保持一致。

去重键使用同一规范化函数处理书名和作者，减少空格、大小写及常见标点造成的重复项。

## 兼容性与错误处理

- 不改变 API 请求和响应结构。
- 不改变书源规则格式。
- 远程书源请求失败仍按当前逻辑忽略该源并记录日志。
- 书名和作者都为空的项目视为无匹配。
- 作者搜索继续支持；短关键词不会因阈值过严而丢失所有结果。

## 测试策略

先添加失败测试，再实现代码：

- 完全一致、前缀、包含和作者匹配的排序顺序；
- 空格、大小写、书名号和常见标点的规范化；
- 正常关键词过滤无关结果；
- 单字中文及两字符 ASCII 关键词只排序、不硬过滤；
- 同分项目保持原始顺序；
- 结果严格截断为 50 条；
- 多源合并使用规范化去重键；
- SSE 一个批次超过剩余名额时不会突破总上限。

验证包括相关模块测试、全部 Rust 测试以及前端构建。

## 范围外

本次不做：

- 拼音、错别字、编辑距离或语义向量搜索；
- 修改远程书源的搜索规则；
- 新增高级搜索语法或作者输入框；
- 为流式 SSE 缓冲所有书源以实现跨源全局排序。
